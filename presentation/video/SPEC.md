# 発表動画の演出仕様

原稿(`../script.md`)を読み上げる 4〜5 分の発表動画。場面は原稿の 9 節と 1 対 1 で対応する。

## 狙い

見終わった人が「ゲームの更新から mod の修正までを、実データで数字にしているシステム」と一言で言えること。

## 出力

HyperFrames、1920×1080、30 fps。ナレーションは本人の録音。録音を編集したあと、各場面の長さと切り替え(`compositions/*.html` の先頭の `CUES`)を音声に合わせる。録音前は原稿の文字数から見積もった仮の長さ(1 分あたり約 300 字)で組む。

## 見た目

ダッシュボード自体の見た目をそのまま大きくして使う(`web/style.css` の色)。

| 役割 | 値 | 使う場所 |
|---|---|---|
| 背景 | `#f9f9f7` | 全場面 |
| カード | `#fcfcfb`、枠 `rgba(11,11,11,0.10)`、角丸 12px | グラフや表を置く面 |
| 文字 | `#0b0b0b` / 補足 `#52514e` / 控えめ `#898781` | |
| 目盛り線 | `#e1e0d9` | |
| 強調(青) | `#2a78d6` | データと、1 場面に 1 か所の強調語 |
| 旧版(橙) | `#eb6834` | 修正前の版と、それが使われた期間だけ |
| ゲームの更新 | `#2e2d2a`(大型は実線、パッチは破線) | グラフの縦線 |

- 文字: 日本語は Noto Sans JP(見出し 700、本文 400)、数字は Inter の等幅数字(`font-variant-numeric: tabular-nums`)
- 見出しは 64〜96px、本文で読ませる文字は 32px 以上
- 影はカードにだけ: `0 2px 8px rgba(11,11,11,0.06)`

## 動き

- 登場: `expo.out` 0.5〜0.7 秒。退場は登場の半分の長さで `power3.in`
- グラフは読む順に組み立てる: 軸 → 基準線 → データ → 注目点への注記 1 つ
- 数字のカウントアップは 1.4 秒で、そのあと止める
- 図は話した部分から 1 つずつ出す。完成した図を一度に出さない
- 着地した見出しは動かさない

## 使わないもの

暗い背景に小さな要素が浮かぶ画面、光彩・パーティクル・グラデーション、ガラス風のカード、3 枚並びのカードや KPI の並び、暗くしたスクリーンショットに重ねた見出し、隅に置いたロゴ、全要素が同じフェードとスライドで入る動き、着地後も動き続ける見出し、ナレーションと同じ文の字幕。

## 数字

すべて `assets/data.js`(`../tools/fetch-data.mjs` が公開 API から生成)から読む。場面の中に数字を直接書かない。画面に出す数字には出どころ(取得日、Thunderstore のみ、多めの見積もり など)を小さく添える。

## 確認するフレーム

- 1: 10/28 の線が落ちた直後、6 個が橙になった時点
- 5: 50 秒の経路と Blob の経路が切り替わる前後
- 6: 712 が出た時点(1 の「? 回」と同じ位置・大きさで答えが入っているか)
- 9: 最後のフレーム

## 選ばなかった案

- 「6,212 という数字の旅」: 1 つのダウンロード数を API の応答から画面の点まで 1 カットで追う。技術の説明は濃くなるが、企画書のページとの対応が弱い
- 「企画書がそのまま動く」: 企画書の各ページを順に見せる。企画書とは揃うが、最初の 30 秒で引き込む材料がない
